| Field | Value |
|-------|-------|
| **AVE ID** | AVE-2026-0044 |

| **Aliases** | Silent Model Swap, Provider Version Drift, Foundation Update Blast |
| **Category** | structural |

| **Affected Frameworks** | any (provider-hosted foundation models) |
| **Models Observed** | gemini-2.5-flash, gpt-4o, claude-3-5-sonnet |

---

## Summary

A provider-side foundation-model update — a new minor version, a silent alias
re-point (e.g. `gemini-2.5-flash`, `gpt-4o`), or a default-routing change —
alters output distribution, schema adherence, refusal behaviour, or latency
**without any change to the customer's code or prompt**. Every agent pinned to
the moving target degrades at the same moment.

Because many tenants share the same upstream model, a single update is a
**correlated, fleet-wide failure event**. This is the defining accumulation
risk for an agent insurer: the independent-risk assumption behind per-agent
pricing breaks because the losses arrive together.

---

## Mechanism

1. An agent is deployed against a model reference that is **not immutably
   pinned** — an alias, a `latest` channel, or a minor version the provider
   hot-swaps under the same name.
2. The provider ships an update. One or more of: instruction-following,
   JSON/tool-schema adherence, refusal thresholds, or token economics shift.
3. Validation that passed at **bind time** no longer holds at **runtime** — but
   no deploy happened on the customer side, so **no CI gate fired** and nothing
   was retested.
4. The same model backs many customers, so the degradation is **correlated**
   across the whole book rather than independent per agent.

### Failure modes observed

- **Broken output schema** — downstream automation consuming the agent's JSON
  silently corrupts or halts (the original motivating production case).
- **Dropped guardrails** — a jailbreak that was previously refused now complies
  after a refusal-threshold change.
- **Cost/latency runaway** — a routing change inflates tokens or response time
  past SLA.

---

## Blast Radius

- **Correlated, fleet-wide, simultaneous.** One upstream change can break *N*
  dependent agents across *N* tenants at the same instant.
- **Accumulation risk.** Independent-risk pricing fails; the insurer's exposure
  concentrates into a single moment rather than spreading across the book.
- **Defeats per-agent isolation.** No tenant did anything wrong; the failure is
  upstream and shared.
- Requires a **cohort-level** detection and a **cohort-level** response — mass
  notification plus per-tenant kill-switch — not per-agent handling.

---

## Evidence

Demonstrated via the Neuravant cohort-escalation pipeline: a single simulated
upstream cascade fans out to 50 tenant webhooks with signed, idempotent,
retried delivery (50/50 delivered) while a single internal incident is raised —
modelling the production case "an updated LLM breaks the workflow for 50 clients
at once."

| Component | Role |
|-----------|------|
| `nail.monitoring.notify.WebhookFanout` | Machine→machine cohort fan-out (kill-switch trigger) |
| `nail.monitoring.notify.KnockProvider` | Machine→human cohort notification (thin payload) |
| `alert_engine.AlertEscalationEngine.escalate_cohort` | Orchestrates both planes + single internal PagerDuty |
| `test_notify.py::test_escalate_cohort_integration` | 50/50 delivery under fault injection |

## Defences

### 1. Immutable Model Pinning *(preventive)*
Bind agents to fully-qualified, immutable model versions (dated snapshots),
never to aliases or `latest`. Treat any provider version change as a **deploy**
that must pass the frozen acceptance gate before promotion.

### 2. Continuous Acceptance Re-Validation *(detective)*
Re-run the bind-time acceptance/adversarial suite on a cadence **and** on
provider-update signals. A drop below the bound threshold flags an upstream
cascade *before* downstream loss. (NAIL `continuous_reaudit`.)

### 2b. Upstream Model-Version Watcher *(detective — implemented)*
`nail.monitoring.model_watcher.ModelVersionWatcher` polls each provider's
model-metadata endpoint (google/openai/anthropic), fingerprints the in-use
models, and on a version change **automatically** fires the affected agent
cohort to `/api/internal/cohort-incident`. Read-only and key-light; never
false-fires on first observation, a transient API error, or an empty cohort.
This is what makes the cascade response autonomous rather than operator-driven.

### 3. Cohort Escalation + Per-Tenant Kill-Switch *(mitigating)*
On a correlated break, fan out **signed, idempotent, retried** webhooks to every
affected tenant — each fires its own kill-switch to revoke agent keys/endpoints
and cap liability — plus **one** Knock workflow trigger to notify all client
orgs' people. PagerDuty fires **once** internally (Neuravant on-call), never
per-client. See `nail.monitoring.notify`.

## Key Insight

> Per-agent risk models assume independent failures. A shared upstream model
> makes failures **correlated**: the entire insured book can degrade in one
> instant from a change no customer made and no CI pipeline saw. The actuarial
> answer is to price accumulation risk explicitly, pin models immutably, and
> hold a cohort-scale response primitive (mass kill-switch + mass notification)
> ready before the cascade arrives.
